# Terraform — the `base-vm` module

Stage 2 of the pipeline, as far as the core layer is concerned: the one
reusable module every VM in the homelab is built from. Core has **no
Terraform projects and no state** — the projects live with what runs on them:

| Repo | Project | TFC workspace |
|---|---|---|
| [homelab-proxmox-monitoring](https://github.com/colac/homelab-proxmox-monitoring) | `terraform/` | `Monitoring` |
| [homelab-proxmox-workloads](https://github.com/colac/homelab-proxmox-workloads) | `nextcloud/terraform/` | `Nextcloud` |
| [homelab-proxmox-workloads](https://github.com/colac/homelab-proxmox-workloads) | `k3s/terraform/` | `k3s` |

Terraform owns only the VM's **existence and shape** — CPU, memory, disks,
network, and the cloud-init user/SSH key. Everything running inside the VM is
Ansible's job.

## Consuming the module

Projects pin it to a release tag of this repo:

```hcl
module "nextcloud" {
  source = "git::https://github.com/colac/homelab-proxmox.git//terraform/modules/base-vm?ref=v2.0.0"

  vm_name        = var.vm_name
  template_name  = var.template_name   # a template this repo's Packer built
  cpu_cores      = var.cpu_cores
  # ...
  ssh_public_key = file(pathexpand(var.ssh_public_key))
}
```

- **Pin a tag, never a branch.** A module change rolls out project by
  project: bump one `ref`, `terraform init -upgrade`, read the plan.
- **`template_name` is the other half of the contract.** It names a template
  built by [../packer](../packer/README.md); renaming or renumbering one breaks
  every project that clones it.
- Inputs and outputs: [modules/base-vm/README.md](modules/base-vm/README.md)
  (generated by `terraform-docs`).

Validating the module here needs no credentials and no backend:

```bash
mise run tf:validate
```

## What `base-vm` does

Wraps a single `proxmox_vm_qemu` resource with the settings that make a
Packer template clone reliably:

- **`full_clone = true`** — an independent copy, not a linked clone.
- **`boot = "order=scsi0"`** — boots the cloned OS disk, not the cloud-init
  drive or the network.
- **`scsihw = "virtio-scsi-single"`** — must match what the template was built
  with, or the disk isn't found.
- **cloud-init** — `ciuser` + `sshkeys` only. This is the one place cloud-init
  is used, and only for login access; app config is Ansible's.
- **`agent = 1`** — the QEMU guest agent is what lets Terraform report the
  VM's DHCP-assigned IP as an output.
- **`data_disk_size`** — an optional second disk, turned into `docker-vg` by
  the `colac.homelab.docker_data` role. `null` for a VM meant to *receive* an
  existing data disk.

Outputs: `vm_name`, `vm_ip`, and `ansible_inventory_line` — a ready-to-paste
line for the consumer's Ansible inventory.

## Rules every consuming project follows

**One project = one VM = one Terraform Cloud workspace = one state file.** A
`terraform apply` for Nextcloud must never be able to touch the monitoring VM,
and each can be destroyed and rebuilt on its own.

State lives in Terraform Cloud (org `colac_homelab`), but **execution must be
Local**: Proxmox is on the LAN and unreachable from TFC's runners. Set it per
workspace: [Terraform Cloud](https://app.terraform.io/app/) → Workspace →
Settings → Execution Mode → **Local**. Forgetting shows up as a run that cannot
reach the Proxmox API.

Credentials reach Terraform only inside `mise run tf:*` tasks, through each
repo's `.mise/sops-exec terraform` profile: `TF_VAR_pm_api_url`,
`TF_VAR_pm_api_token_id`, `TF_VAR_pm_api_token_secret`,
`TF_VAR_pm_tls_insecure`, and `TF_TOKEN_app_terraform_io` when `tf_cloud_token`
is set. A bare `terraform plan` gets none of them, by design.

### Gotchas

- **Disk size can only grow.** `disk0_size` must be **≥** the template's disk.
  The Telmate provider cannot shrink a cloned disk; instead of failing, it
  silently creates a new empty one and the VM boots to nothing.
- **The provider pin is load-bearing.** `Telmate/proxmox 3.0.2-rc07` is pinned
  in the module and in every project's `versions.tf`; mixing versions breaks
  `terraform init`. Bump it here first, release, then in each project.
- **TLS verification is on** (`pm_tls_insecure = false`) because the Proxmox
  host has a valid certificate for its hostname — which only resolves through
  PiHole. Keep PiHole as your DNS while running Terraform.
- **No IP is assigned by Terraform.** VMs take DHCP; give anything long-lived a
  DHCP reservation so its address doesn't move under Ansible's inventory.
- **`sockets` is deprecated** in the provider (`cpu { sockets = }`); changing
  it touches every consumer's plan, so it is tracked in [../TODO.md](../TODO.md)
  rather than done as a drive-by.

## Create the Terraform user in Proxmox

A platform task, done once, so it is documented here even though the token is
used by the other repos. Run in the Proxmox node console:

```bash
# create role and set privileges
pveum role add TerraformRole -privs "Datastore.AllocateSpace Datastore.AllocateTemplate Datastore.Audit Pool.Allocate Pool.Audit Sys.Audit Sys.Console Sys.Modify VM.Allocate VM.Audit VM.Clone VM.Config.CDROM VM.Config.Cloudinit VM.Config.CPU VM.Config.Disk VM.Config.HWType VM.Config.Memory VM.Config.Network VM.Config.Options VM.Migrate VM.PowerMgmt VM.GuestAgent.Audit SDN.Use"

# create user (choose your own password)
pveum user add terraform@pve --password 'CHANGE_ME'

# set permissions
pveum aclmod / -user terraform@pve -role TerraformRole

# create API token — prints the secret exactly once
pveum user token add terraform@pve terraform-automation --privsep 0
```

The token ID and secret go in the `secrets.yaml` of **each repo that runs
Terraform** (monitoring, workloads) as `proxmox_terraform_token_id` /
`proxmox_terraform_token_secret` — not in this repo's, which only builds
templates. It is a *different* token from Packer's: Packer needs
template-build rights, Terraform needs clone/configure rights, and neither
should carry the other's.

A separate token per repo (`terraform-monitoring`, `terraform-workloads`) is
the next step in least privilege: revoking one then cannot break the other.
`pveum user token add terraform@pve terraform-monitoring --privsep 0` creates
it under the same role.
